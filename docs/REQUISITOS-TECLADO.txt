SISTEMA COMPLETO DE TECLADO MATEMÁTICO ACCESIBLE

La aplicación debe incorporar un sistema avanzado de control mediante teclado diseñado específicamente para una persona ciega.

El objetivo es que prácticamente todas las funciones matemáticas importantes puedan ejecutarse sin mouse y sin tener que recorrer visualmente botones.

Debe existir un apartado específico llamado:

“Teclado y atajos”

Este apartado debe permitir:

Consultar todos los atajos.
Escuchar todos los atajos.
Buscar una función.
Buscar qué hace una tecla.
Personalizar teclas.
Restaurar configuración predeterminada.
Activar o desactivar el modo de teclado matemático.
Practicar los atajos sin ejecutar operaciones.
Crear combinaciones personalizadas.
DOS MODOS DE TECLADO

Implementar claramente dos modos:

1. MODO ESCRITURA

Es el modo normal.

Las teclas sirven para escribir expresiones.

Ejemplo:

x^2 + 5*x - 3

Los números y letras deben escribirse normalmente.

No interceptar innecesariamente:

Letras.
Números.
Espacio.
Backspace.
Delete.
Flechas.
Home.
End.

cuando el usuario está escribiendo dentro de un campo.

2. MODO TECLADO MATEMÁTICO

Crear un modo especial donde las teclas físicas funcionan como comandos matemáticos.

Debe poder activarse y desactivarse fácilmente.

Cuando se active, anunciar por voz:

“Modo teclado matemático activado.”

Cuando se desactive:

“Modo escritura activado.”

Debe existir siempre una forma sencilla de saber qué modo está activo.

El estado también debe estar disponible para lectores de pantalla mediante ARIA.

SEGURIDAD DEL MODO TECLADO

Nunca secuestrar todas las teclas permanentemente.

El modo matemático debe funcionar únicamente cuando:

Está activado explícitamente.
El foco está dentro del área de trabajo de MathVoice.
El usuario no está escribiendo en un input o textarea, salvo combinaciones específicas.

No interferir con:

NVDA.
JAWS.
VoiceOver.
Navegador.
Sistema operativo.

No sobrescribir atajos importantes como:

Ctrl + L
Ctrl + T
Ctrl + W
Ctrl + R del navegador
Alt + F4
Ctrl + Shift + T
Ctrl + Tab
Alt + Tab

Tener especial cuidado con combinaciones utilizadas por lectores de pantalla.

NUNCA USAR ROLE=APPLICATION GLOBALMENTE

No convertir toda la página en role="application" únicamente para capturar teclado.

Esto puede romper la navegación convencional de lectores de pantalla.

Si en algún componente especializado fuera estrictamente necesario, limitarlo al componente concreto y justificarlo.

Preferir controles HTML semánticos y manejo contextual de eventos.

OBJETIVO DEL SISTEMA DE TECLADO

Una persona ciega que conozca MathVoice debería poder realizar la mayoría de sus cálculos prácticamente sin usar Tab.

Ejemplo:

Activar modo matemático.

Presionar D.

Escribir:

x^3

Enter.

Escuchar:

“Resultado. Tres equis al cuadrado.”

Y continuar trabajando inmediatamente.

Pero una persona que no recuerde D debe poder:

Abrir la paleta de comandos.
Escribir “derivada”.
Pulsar Enter.
Obtener exactamente la misma función.

Nunca obligar al usuario a memorizar los atajos.

Los atajos deben acelerar el uso, no ser un requisito para poder utilizar la aplicación.

CRITERIO DE FINALIZACIÓN

El sistema de teclado NO está terminado solamente porque los shortcuts responden.

Debe verificarse que:

Se pueden descubrir.
Se pueden aprender.
Se pueden escuchar.
Se pueden cambiar.
Se pueden restaurar.
No interfieren con escritura.
No interfieren con lectores de pantalla.
El usuario sabe en qué contexto está.
La misma tecla puede tener acciones contextuales sin causar confusión.
Siempre existe una alternativa a memorizarla.
Los errores son anunciados.
El usuario puede cancelar cualquier operación.

El objetivo final es que una persona completamente ciega pueda llegar a manejar MathVoice de forma extremadamente rápida utilizando principalm
